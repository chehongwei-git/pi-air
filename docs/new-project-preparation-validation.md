# 新建项目自动准备 Pi：验证记录

## 结论与范围

当前工作区实现已通过 Windows 本机全量自动化验证。浏览器使用系统 Edge 和真实 Svelte 页面，仅模拟 Tauri IPC；不会向在线模型发送请求。尚未完成 macOS、Linux 或三平台原生客户端交互验收、CI 与原生打包，不作为发布完成记录。

主动新建明确项目时自动连接 Pi、读取目录并应用初始选择；准备期间允许编辑文字和附件，暂不发送或切换模型。首次发送复用准备后的实例。未发送草稿重访复用同一对象，启动和旧目录的迟到结果不覆盖当前项目。详细行为见 [交互说明](interaction.md#模型与服务商)。

## 关键回归覆盖

- 冷启动连接失败后直接新建项目，仍能独立准备并读取模型；准备本身不提交 prompt。
- 启动设置尚未读完时选择目录、启动连接迟到、来源模型目录迟到：目标对象和目标模型目录不被覆盖。
- 慢连接时编辑输入、保留附件引用、重复选择和切换项目：连接合并、不抢导航、不重置草稿。
- 已准备但未发送的草稿重访：对象、输入和显式模型选择保持，实例不重复启动。
- 准备期间按钮和回车均不发送；状态层直接调用发送时等待既有准备任务；首条发送复用实例且只提交一次。
- 连接失败保留草稿，手动重试不自动发送；失效项目偏好明确报错，可显式改选可用模型恢复。
- 已连接但模型目录读取失败：不误报连接故障，保留输入，独立重试不重启实例，恢复后搜索焦点保留。
- 目录加载和初始模型应用期间避免交错选择；成功空目录提供模型设置入口。
- 旧长对话 DOM 身份和阅读窗口、多项目并发队列、后台交互、归档、设置、长文本剪切与撤销均随完整浏览器套件通过。
- 浅色准备状态及深色窄窗口模型/思考面板已检查实际截图；浏览器覆盖缩放、键盘与焦点。底部为用量指标预留行高，准备前后输入位置的断言通过。

本地截图由浏览器套件生成在 `test-results/`，例如 `new-project-preparing-light.png` 和 `composer-controls-dark-narrow.png`；这些是本机测试产物，不提交到版本库。

## 排查与测试夹具修正

最初全量浏览器回归中有旧测试仍等待“首次发送才启动”的信号。相应夹具已按真实宿主契约调整：新会话返回空历史，独立运行时保存各自状态，预热会话的 prompt 也遵守全局并发队列。保留旧对话 DOM、排队、实例数量、草稿和扩展状态的等效断言。

长文本剪切失败的 trace 记录了 Vite 连接丢失及页面重新加载，输入事务被页面重载打断。仅在 `browser-test` 模式关闭 HMR，开发模式保持原配置；原剪切内容一致性和撤销断言完整保留并通过。早期浏览器全局预热还发生过与 Rust 编译并行时的加载超时，最终全量浏览器验证单独串行运行。

最后一次完整浏览器运行正常结束并返回退出码 0。此前一轮虽然已生成 `130 passed` 及 `.last-run.json` 的 `passed` 状态，但工具调用被中断、没有取得退出码，因此另行完整运行确认，而不是将中断视为成功。
